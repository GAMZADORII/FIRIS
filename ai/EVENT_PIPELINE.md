# 이벤트 저장과 처리 지연

멀티 카메라 워커는 카메라마다 영상 읽기·화면 갱신, 모델 추론, MP4 저장을 분리합니다.
추론은 카메라당 한 건만 진행하며, 완료되면 최신 프레임을 다음 입력으로 사용합니다.
공유 모델은 기존처럼 한 번에 하나의 추론만 수행합니다. 모델 처리량 자체가 늘어나는 것은 아닙니다.

판정에는 완료된 추론을 한 번씩만 사용하고, 결과가 나온 시간이 아니라 입력 프레임의 시간을 사용합니다.
처리 지연이 생겨도 검출 비율 70%, 최소 분석 횟수, 박스 영역 일치 조건은 유지합니다.
필요한 분석 횟수에 해당하는 실제 시간 간격의 합에 따라 판정 구간을 기본 2초에서 최대 30초까지 늘립니다.
dev 브랜치 기준으로 최소 분석 결과는 2개이며, 감지 지속 시간 2초와 검출 비율·영역 일치 조건도 충족해야 합니다.
6초보다 오래된 추론 결과는 버리고, 관측 간격이 6초를 넘으면 판정 기록을 초기화합니다.
같은 화재가 계속 보이는 동안에는 이벤트를 반복 생성하지 않습니다.

영상은 감지 확정 시점 전후 5초를 저장합니다. 원본 시작·끝에서는 확보한 구간만 저장합니다.
MP4 인코딩과 미디어 등록은 별도 작업에서 실행하고, 파일 처리 종료 시 완료를 기다립니다.
카메라당 저장 작업은 최대 두 건까지만 유지합니다. 저장이 계속 밀리면 로그를 남기고 기다리며 버리지 않습니다.
이벤트 최초 등록과 스냅샷 저장은 아직 동기 처리입니다.
저장 실패 시 이벤트 ID와 예외를 기록합니다. 기존 누락 영상 자체를 복구하지는 않습니다.
`--loop`에서는 저장 성공 여부와 관계없이 매 재생마다 다시 분석하고, 감지 조건을 충족하면 새 이벤트를 저장합니다.

## 로그 확인

- `event_created`: 백엔드 이벤트 등록 완료
- `media_saved`: 원본·박스 영상 저장 및 백엔드 미디어 등록 완료
- `insufficient_samples`: 실제 분석 결과 부족, 판정 대기
- `waiting_for_duration`: 지속 시간 부족
- `insufficient_positive_ratio`: 검출 비율 부족
- `inconsistent_region`: 박스 영역 불일치
- `duplicate_suppressed`: 같은 화재의 중복 이벤트 억제
- `stale_inference`: 너무 늦게 도착한 결과 제외
- `media_save_failed`: 인코딩 또는 미디어 등록 실패, 같은 로그의 이벤트 ID 확인
- `waiting_for_files`: 처리할 새 파일 대기
- `replay_detection`: 반복 재생에서도 감지·이벤트 저장 활성화

## 적용

기존 AI 워커를 종료한 후 `ai` 디렉터리에서 다시 실행합니다.

```powershell
py -m app.services.multi_camera_service --model yolo --sample-fps 3 --loop
```

`--loop`는 화면을 반복 재생하며 같은 파일도 매 재생마다 새 이벤트를 생성할 수 있습니다.
한 번의 재생 안에서는 같은 화재가 지속되는 동안 중복 생성을 억제하며, 다음 재생에서 판정 상태를 초기화합니다.
이 변경은 기존 DB 이벤트나 저장 영상을 수정하지 않습니다.
